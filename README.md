# Git 변경 내용으로 커밋·PR 문안 만들기

Git 변경 내용을 읽어 한국어 커밋 제목이나 PR 문안을 제안합니다.
**Git 커밋을 실행하거나 PR을 생성하지는 않습니다.**

## 빠른 시작

Python 3.10 이상과 Git이 필요합니다. 추가 Python 패키지는 필요 없습니다.
아래 경로를 실제 **도구 폴더**와 **대상 Git 저장소**로 바꾸세요. Make 명령은 도구 폴더에서 실행합니다.

```sh
cd /path/to/TOOL_DIR
make preview-commit REPO='/path/to/your-repo'
make preview-pr REPO='/path/to/your-repo' ARGS='--staged --safe-mode'
```

미리보기는 AI에게 보낼 내용(JSON)만 보여 줍니다. 키를 읽거나 AI 서버를 호출하지 않습니다.
**기본 미리보기에는 원본 변경 내용(diff)이 보입니다.** 민감한 내용이 있는지 확인한 뒤 공유하세요.

실제 문안을 만들려면 API 키(인증 키)가 필요합니다. 도구 폴더의 `.env`에 `AI_API_KEY=값`을 저장하거나 환경변수로 키를 설정하세요. `.env`는 자동으로 읽으므로 `source`할 필요가 없습니다.

```sh
make commit REPO='/path/to/your-repo'
make pr REPO='/path/to/your-repo' ARGS='--staged --safe-mode'
```

| 하고 싶은 일 | Make 명령 |
| --- | --- |
| 커밋 요청 미리보기 | `make preview-commit` |
| PR 요청 미리보기 | `make preview-pr` |
| 커밋 제목 생성 | `make commit` |
| PR 제목·본문 생성 | `make pr` |

`REPO`를 생략하면 현재 Make 작업 폴더의 저장소를 사용합니다.
`ARGS='...'`에는 CLI 옵션을 넣습니다. 공백이 있는 경로는 따옴표로 감싸세요.

<details>
<summary>Make 없이 Python으로 실행하기</summary>

대상 저장소로 이동한 뒤 도구의 `main.py`를 실행합니다.
옵션은 `commit` 또는 `pr` 뒤에 놓습니다.

```sh
cd /path/to/your-repo
python3 /path/to/TOOL_DIR/main.py commit --dry-run
python3 /path/to/TOOL_DIR/main.py pr --staged --dry-run
# 키를 설정한 뒤 실제 문안 생성
python3 /path/to/TOOL_DIR/main.py commit
```

</details>

## 변경 선택과 옵션

기본 입력은 **Git이 이미 관리하는 파일 중 아직 `git add`하지 않은 수정**입니다.
`--staged`를 붙이면 `git add`로 골라 둔 변경만 사용합니다.
새 파일의 내용도 넣으려면 대상 저장소에서 먼저 `git add`로 선택하세요.

| 옵션 | 기본값 | 역할·범위 |
| --- | --- | --- |
| `--staged` | 꺼짐 | `git add`로 골라 둔 변경만 사용 |
| `--dry-run` | 꺼짐 | 키 조회·API 호출 없이 요청 미리보기 |
| `--model` | `gpt-5-mini` | `gpt-5-mini`, `gpt-5.5`, `gpt-5.4`, `gpt-5.4-mini` 중 선택 |
| `--temperature` | 미지정 | 표현의 다양성 설정. 0~2의 유한한 숫자 |
| `--max-tokens` | 미지정 | 응답의 출력 토큰 상한. 양의 정수 |
| `--safe-mode` | 꺼짐 | 민감정보 패턴 가리기와 입력량 제한 |
| `--max-files` | 10 | safe mode에서 포함할 파일 수. 양의 정수 |
| `--max-lines` | 200 | safe mode에서 포함할 변경 내용 줄 수. 양의 정수 |

지원하지 않는 모델과 잘못된 숫자는 Git 조회·API 호출 전에 거부합니다.
전체 도움말: `python3 main.py commit --help` 또는 `python3 main.py pr --help`.

<details>
<summary>temperature·max_tokens 선택과 미리보기 예시</summary>

| 설정 | 의미와 주의점 |
| --- | --- |
| `temperature` | 지원하는 모델에서 낮을수록 표현 변화가 줄고 높을수록 다양해지는 경향이 있습니다. 정확성이나 같은 결과의 반복을 보장하지 않습니다. 생략하면 서버 기본값을 사용합니다. |
| `max_tokens` | 글자 수가 아닌 **출력 토큰 수** 상한입니다. 응답 분량·토큰 사용량·비용에 영향을 줍니다. 입력 토큰과 추가 호출도 비용에 포함되므로 전체 비용 상한은 아닙니다. 너무 작으면 JSON·필드가 잘려 재생성을 유발할 수 있습니다. 생략하면 요청에 넣지 않습니다. |

두 설정의 지원 여부와 동작은 제공자·모델에 따라 다릅니다.
아래는 **문법·요청 본문 확인용**입니다. API 호환성을 검증하는 예시가 아닙니다.

```sh
# 도구 폴더에서 실행. 대상 저장소에 스테이징된 변경이 있어야 합니다.
make preview-pr REPO='/path/to/your-repo' ARGS='--staged --model gpt-5.4-mini --temperature 0.2 --max-tokens 1024'
```

</details>

<details>
<summary>safe mode와 입력 생략 범위</summary>

- `--safe-mode`는 선택 사항입니다. 일반적인 API 키, `api_key`·`token`·`password` 할당값, 이메일 패턴을 가립니다. 생성 문안과 Git 오류도 가립니다. 모든 비밀을 찾는다고 보장하지는 않습니다.
- 기본 제한은 파일 구간 10개, diff 200줄입니다. `--max-files`·`--max-lines`로 바꿀 수 있습니다. 줄 수에는 헤더와 메타데이터도 포함합니다.
- 앞에서부터 담으므로 마지막 파일 구간은 중간에 잘릴 수 있습니다. 미리보기의 `truncation`에 포함·제외 수를 표시합니다. 생략된 내용은 문안에서 추정하면 안 됩니다.
- 미추적 파일은 경로만 표시하고 내용은 읽지 않습니다. safe mode에서는 경로도 `max-files`개로 제한하고, 범위 밖 경로가 드러나지 않게 상태 목록을 생략합니다.
- 선택한 변경이 없으면 종료합니다. 미추적 파일만 있으면 일반 생성은 스테이징 안내 오류를 냅니다.

</details>

## safe mode 처리 전·후 파일

`--safe-mode`로 실행하면 대상 Git 저장소 루트의 `safe-mode-output/before`에 원본 diff, `after`에 마스킹·입력량 제한을 적용한 diff를 저장합니다. `after`는 AI에게 보내는 변경 내용과 같으며, 전송 방식은 바뀌지 않습니다. 미리보기에서도 저장하지만 키를 읽거나 API를 호출하지 않습니다.

**`before`에는 가리지 않은 민감정보가 들어갈 수 있습니다.** 두 파일은 다음 실행 때 덮어씁니다. 지원하는 환경에서는 폴더 0700·파일 0600 권한을 사용하며 Git 수집 대상에서 제외합니다. 다른 저장소의 `.gitignore`나 Git 설정은 수정하지 않습니다.
심볼릭 링크·특수 파일·이미 Git이 관리하는 출력 경로 등 안전하지 않은 대상에는 쓰지 않습니다. 저장에 실패하면 API 호출 전에 오류로 끝나며 일부 출력 파일은 남을 수 있습니다. safe mode를 끄면 저장하지 않습니다. 변경이 없으면 기존 조기 종료에 따라 새 파일을 만들거나 기존 파일을 갱신하지 않습니다.

## 출력 예시

아래는 `demo.txt`가 `blue`에서 `green`으로 바뀐 **같은 스테이징 변경**을 가정한 합성 예시입니다.
실제 API 생성 결과나 테스트 실행 결과가 아닙니다.

커밋 출력:

```text
## 커밋
demo.txt의 색상 값을 `green`으로 변경
```

PR 출력:

```text
demo.txt의 색상 값을 `green`으로 변경

## 변경 이유
- 예시 파일의 색상 값을 갱신합니다.

## 변경 내용
- demo.txt에서 `blue`를 `green`으로 변경합니다.

## 테스트 방법
- 스테이징된 demo.txt 변경을 확인합니다. 이 항목은 실행 결과가 아닌 제안입니다.
```

이 변경을 대상으로 문안을 요청하는 명령:

```sh
make commit REPO='/path/to/demo repo' ARGS='--staged'
make pr REPO='/path/to/demo repo' ARGS='--staged'
```

<summary>출력 검증·재생성의 범위와 한계</summary>

| 검사 | 규칙 |
| --- | --- |
| 길이 | 커밋 제목 72자, PR 제목 80자, PR 목록의 각 항목 1,000자 이하. 표시 헤더는 제외합니다. |
| 파일 근거 | 커밋 제목에는 변경 파일 이름, PR의 변경 내용에는 변경 파일 경로가 필요합니다. 모든 파일명이 제목 제한보다 길면 ‘파일’로 구체적인 변경을 설명합니다. |
| 한국어 | 제목·본문은 한국어로 요청합니다. 파일명·명령·고유명사·내부 JSON 키는 번역하지 않습니다. |
| 테스트 문구 | 실행 결과가 아닌 제안만 허용합니다. 근거 없는 영어·한국어 테스트 결과 주장은 거부합니다. |

공백 정리와 PR 헤더 조립은 추가 API 호출 없이 처리합니다.
JSON·필드·목록·빈 텍스트·길이·한국어 검사에 실패하면 한 번 다시 생성합니다. **전체 API 시도는 최대 두 번**입니다.
임의로 자르거나 빠진 내용을 만들어 넣지 않아 의미·자연스러운 표현을 유지할 기회를 주지만, 시간과 비용이 더 들고 두 번째도 실패하면 오류로 끝납니다.
파일 근거·테스트 결과 주장 오류, 네트워크·인증·API 전송·응답 외피 오류는 재시도하지 않습니다.

한국어 검사는 실제 경로, 백틱 기술 용어·명령, 일부 고유명사·약어·마스킹 표시를 제외한 문자 비율을 봅니다.
한글 음절 두 개 이상, 남은 문자 중 60% 이상을 요구합니다. 테스트 방법에는 diff에 실제 나온 백틱 명령만 단독으로 적어도 됩니다.
문자 비율과 정해진 표현만 검사하므로 과도한 거부나 누락이 있을 수 있습니다. 언어의 완전한 판별이나 의미·품질을 보장하지 않습니다.
최종 문안은 원본 diff와 대조해 사용하세요.

</details>

<details>
<summary>API 키·.env 상세 규칙</summary>

키 조회 순서는 다음과 같습니다. 비어 있는 값은 건너뜁니다.

1. 환경변수 `AI_API_KEY`
2. 환경변수 `OPENAI_API`
3. **도구 루트**의 `.env` (`AI_API_KEY` 우선, 다음 `OPENAI_API`)

대상 저장소의 `.env`는 읽지 않습니다. Make·직접 Python 실행에 같은 규칙을 적용합니다.
키가 없으면 설정 안내를, 파일 읽기·문법 오류면 값과 원문을 숨긴 오류를 출력합니다.
환경변수에 키가 있거나 미리보기·도움말·인자 오류·변경 없음·미추적 파일만 있는 경우에는 `.env`를 읽지 않습니다.

| `.env` 항목 | 지원 범위 |
| --- | --- |
| 파일·키 | UTF-8. `AI_API_KEY=값`, `OPENAI_API=값`만 읽습니다. 다른 키·빈 줄·주석은 무시합니다. |
| 공백·중복 | 앞뒤 공백, 선택적인 `export` 접두사를 허용합니다. 같은 키는 마지막 값을 사용합니다. |
| 값 | 한 줄 텍스트 또는 전체를 작은따옴표·큰따옴표로 감싼 값. 따옴표 없는 값에 따옴표를 섞을 수 없습니다. |
| 주석 | 따옴표 밖 `#`가 맨 앞이나 공백 뒤에 있으면 주석입니다. 닫는 따옴표 뒤에는 공백·주석만 허용합니다. |
| 문자 그대로 | `$VAR`, `${VAR}`, 역따옴표, `$(...)`, 역슬래시를 실행·확장하지 않습니다. 따옴표 안의 같은 종류 따옴표와 이스케이프 해석은 지원하지 않습니다. |

완전한 dotenv·셸 문법이 아닙니다. 파일을 `source`하지 마세요.
요청 주소는 `https://copa.codyssey.kr/v1/chat/completions`로 고정되어 있습니다.

</details>

<details>
<summary>개발용 확인·캐시 정리</summary>

- `make check`: 구문 컴파일·모듈 import·CLI 도움말만 확인하는 기본 검사입니다. 생성 흐름이나 API 전체 검증은 아닙니다.
- `make clean`: 지정된 루트·`b62` 캐시 경로를 즉시 삭제합니다. 심볼릭 링크와 그 아래 경로는 건너뜁니다.

</details>

## 실제 PR에서 초안을 다듬은 예

[PR #1: main.py의 기능을 모듈로 분리](https://github.com/xifoxy-ru/B6-2/pull/1)은 **과거 구조 개선 작업**입니다.
아래는 당시 AI 초안과 실제 최종 문안의 차이이며 현재 기능·검사 결과를 설명하지 않습니다.

1. 길었던 영문 본문을 한국어로 다시 쓰고, 기존 사용법을 유지하는 모듈 분리라는 목적을 앞에 놓았습니다.
2. 마스킹·입력량 제한을 새 기능처럼 소개한 초안의 주장을 기존 기능의 이동으로 바로잡았습니다.
3. 모듈별 긴 나열을 줄이고, 제목은 당시 생성한 커밋 제목을 사용했습니다. 최종 제목은 영문입니다.
4. 제안만 있던 검사 방법을 당시 실제 검사 18개 통과와 기존 함수·클래스 정의 17개가 이동 후에도 같은지 확인한 결과으로 구분했습니다.
5. 검사 파일이 저장소 밖에 있어 내려받은 저장소만으로는 당시 검사를 그대로 재현할 수 없다는 한계를 밝혔습니다.
6. 독립 검토 뒤의 실제 API 초안 생성과 최종 PR 문안은 앞선 제품 검토에 포함되지 않았음을 명시했습니다.
